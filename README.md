# DL2026_Spring_FSD_Zhulpa

Веб-приложение для просмотра погоды (по городу, координатам или по IP) с подбором мемов под условия. Бэкенд отдаёт REST API и раздаёт статику фронтенда; данные о погодных категориях и мемах хранятся в PostgreSQL.

## Стек

| Слой | Технологии |
|------|------------|
| **Бэкенд** | Node.js (ES modules), Express 5, Sequelize, драйвер `pg`, Axios, dotenv |
| **База данных** | PostgreSQL |
| **Фронтенд** | HTML, CSS (SCSS → CSS), JavaScript (без сборщика бандла) |
| **Внешние API** | OpenWeather (ключ в окружении), геолокация по IP |
| **Опционально** | Docker, Docker Compose |

Структура репозитория: каталог `backend/` — сервер и модели; `frontend/` — разметка, стили и клиентский JS. В режиме разработки фронт и бэкенд настраиваются **отдельно** (см. ниже), после чего страницы открываются через тот же хост и порт, что и API (Express раздаёт файлы из `frontend/`).

## 2.3. Документация по запуску

### Требования

- **Node.js** — рекомендуется актуальная LTS (например 20.x).
- **PostgreSQL** — установленный и запущенный сервер (локально или удалённо), если не используете Docker только для БД.
- Учётная запись [OpenWeather](https://openweathermap.org/api) и **API-ключ** для запросов погоды.

### Настройка окружения

1. Создайте файл `backend/.env` на основе шаблона:

   ```bash
   cp backend/.env.example backend/.env
   ```

   На Windows в PowerShell можно так: `Copy-Item backend\.env.example backend\.env`

2. Заполните переменные в `backend/.env`:

   | Переменная | Назначение |
   |------------|------------|
   | `PORT` | Порт HTTP-сервера (например `4200`) |
   | `DB_NAME`, `DB_USER`, `DB_PASSWORD` | Подключение к PostgreSQL |
   | `DB_HOST`, `DB_PORT` | Хост и порт БД (`localhost` и `5432` при локальном Postgres) |
   | `OPENWEATHER_API_KEY` | Ключ OpenWeather API |

3. В PostgreSQL создайте базу с именем из `DB_NAME` и выдайте права пользователю из `DB_USER` (или используйте существующую БД и пользователя).

4. При первом запуске Sequelize выполнит `sync` схемы. Для заполнения справочников категорий и мемов при необходимости раскомментируйте в `backend/index.js` вызовы `fillWeatherCategories()` и `fillMemes()` (или выполните сидинг по соглашению вашего курса).

### Установка зависимостей

Выполняется **в каждом** из каталогов `backend` и `frontend`:

```bash
cd backend
npm install

cd ../frontend
npm install
```

### Запуск бэкенда

Из каталога `backend`:

```bash
npm run dev
```

или без автоперезапуска:

```bash
npm start
```

Сервер слушает порт из `PORT` в `.env`. Проверка: `http://localhost:<PORT>/api/health` (ответ JSON со статусом).

### Запуск фронтенда (сборка стилей)

Статика подхватывается Express из `frontend/`. Перед открытием сайта нужно **собрать CSS из SCSS** (если вы меняли стили или клонируете репозиторий впервые).

Из каталога `frontend`:

```bash
npm run sass:build
```

При правке SCSS удобно держать отдельный терминал с наблюдением за файлами:

```bash
npm run sass:watch
```

После сборки откройте в браузере `http://localhost:<PORT>/` (тот же порт, что в `backend/.env`), пока запущен бэкенд.

**Итого в типичной разработке:** два терминала — в одном `frontend`: `npm run sass:watch`, в другом `backend`: `npm run dev`; в браузере — корень сайта на порту бэкенда.

### Запуск через Docker (приложение + PostgreSQL)
Пока НЕ запускать так!

Из **корня** репозитория (после настройки `backend/.env` с корректными `DB_*` и ключом погоды):

```bash
docker compose --env-file backend/.env up --build
```

В контейнере приложения `DB_HOST` и `DB_PORT` переопределяются для связи с сервисом БД. Подробности — комментарии в `docker-compose.yml` и `backend/.env.example`.
